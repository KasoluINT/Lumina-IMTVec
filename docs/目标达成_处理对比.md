- 参考：同目录 a1.svg / A2.svg / A3.svg（Lumina + Vecto 风格）
- 项目：`data\candidate`（Lumina-Vec 0.9.2 候选版），新增 `--structure lumina`

## 一、做法

`lumina_vec/regionsvg.py: vectorize_lumina()`：

1. 把输入按 LANCZOS 放大到 ~2.6×（上限 1200 万像素；参考文件的画布也正是原图的 1.7~2.7 倍）；
2. **不做颜色量化**（参考文件的高保真来自"一色块一闭合 path"，量化会掉 3~8 dB）；
3. vtracer `stacked` 模式描摹：每个色块一条闭合 `<path>`，被后画区域包住的部分自然成为**空腔**；
4. 画布保持描摹分辨率（`width/height = 画的尺寸`）——这一点照抄参考文件；若用 viewBox 缩回原图尺寸，
   浏览器在小画布上会把大量小形状合并，实测 PSNR 掉 2.3 dB；
5. 装配成 `<g id="fills" fill-rule="evenodd">`。遮缝描边（`qq3d-gap-filler`）默认关闭：
   参考文件里它是给切片软件用的，画布缩小后会让边界泛色（实测掉 7 dB），需要时传 `gap=True`。

命令行 / Web UI：

```powershell
python -m lumina_vec.pipeline in.png out.svg --structure lumina
```

Web UI 高级选项 → 输出结构 → “Lumina 精确描摹（放大 2.6×，一色块一 path，最接近参考文件）”。

## 二、结果（渲染后与源图逐像素比较，PSNR 越高越接近）

| 图 | 参考 SVG | **本项目 `--structure lumina`** | 差异 |
|---|---|---|---|
| a1.jpg（1600×900，画布 4272×2403） | 27.85 dB | **32.69 dB** | **+4.84 dB（更好）** |
| a2.png（960×1600，画布 2563×4272） | 32.84 dB | **32.37 dB** | −0.47 dB |
| A3.png（973×1600，画布 2598×4272） | 26.07 dB | **27.98 dB** | **+1.91 dB（更好）** |

结构对照（同一套指标，脚本 `data/refsvg/profile.py`）：

| | 参考 a1 / A2 / A3 | 本项目 final-a1 / a2 / A3 |
|---|---|---|
| 形状数 | 6,197 / 2,841 / 12,095（d_blocks÷2） | 210,338 / 65,650 / 398,042 |
| 空腔 | 4,378 / 886 / 2,454 | 由 vtracer stacked 逐层产生（每张数万个） |
| 曲线 | C + Q + A | C（vtracer 样条） |
| 文件 | 23.9 / 9.3 / 27.3 MB | 36.8 / 13.5 / 69.5 MB |

形状数比参考多 4~30 倍：参考的描摹器（Vecto）能用更少的形状贴合边界；我们换成 vtracer 后，
同样的颜色保真需要更多小形状。按“不在乎文件大小、只要还原精度”的前提，这是可接受的取舍。

## 五、已知取舍

1. 形状数远多于参考文件；要压到同一量级可以传 `colors=384`（a2 31.0 dB / 19k path；A3 24.4 dB / 64k path），
   但保真度会低于参考，属于“文件小 vs 更准”的取舍；
2. 曲线只有三次贝塞尔（没有参考文件那种圆弧/二次）；圆弧化还在修（曾出现横扫条纹，已加判据但未启用）；
3. 线条层（一条线一个 path）在本模式中未叠加：细线以“细色块”的形式存在，同样是完整闭合形状；
   需要独立线条层时用 `--structure structured` + `--line-style lens`。
