读法：

1. **他们大量使用圆弧（A）和二次贝塞尔（Q）**，A+Q 占曲线段的一半以上（deep 里 A 就有 27.8 万条）。
   这说明拟合器在"近圆/近抛物线"的段落上直接用弧段，而不是拿一堆三次贝塞尔去逼近。
   效果：同样的形状节点更少、圆形特征（眼睛、瞳孔、高光、发圈）是真正的圆，不会有一圈圈的抖动。
2. **他们的孔洞非常普遍**（deep：34,000 个孔 / 38,350 个形状）。这是"形状 = 自己 + 所有后画的区域"的
   叠放模型——被后画区域包住的部分自然变成洞，也就是你说的"封闭边界图形 + 空腔"。
   我们现在是"面片互不重叠"，只有 581 个孔，结构上更像拼图而不是套娃。
3. **他们是扁平填色，每色一条 path，没有渐变/遮罩**（Lumina 家族）；Illustrator 家族反其道而行：
   用 `linearGradient` 表现光影（spark 54 个），形状数少、每个形状更大。
4. **文件密度**：他们 82~95 字节/段（全精度 float、带空格），我们 31.7 字节/段（2 位小数、无空格）。
   换算下来，我们的节点更多但每个节点更省字。
5. **他们不做 `<style>` 类去重**（Lumina 家族直接把 `fill="#xxxxxx"` 写在每个 path 上）；
   Illustrator 家族用 `.stN` 类，文件小很多。

## 三、反推出来的生成原理

```
① 颜色量化 → 得到若干"色块面片"（每个面片是一块连通同色区域）
② 面片按面积排序，逐个描摹：
     形状 = 自己 ∪ 所有后画的面片        ← 这一步产生空腔（洞）
     边界 = 亚像素等值线 → 用 直线/圆弧/二次/三次 混合拟合
     每条 path 带 fill-rule="evenodd" 和固定颜色
③ 打印/叠色用：给每个形状配一条同色描边遮缝（qq3d-gap-filler，导入端会删掉）
④ 需要光影时：不增加色阶，而是给形状填 linearGradient（Illustrator 家族的做法）
```

**为什么好看**：轮廓是"弧+曲线"拟合出来的（不是台阶）；面片互不重叠但有洞，视觉上没有缝；
同一块颜色只有一个形状，放大不会出现像素格；圆形特征用真圆，边缘不会抖。

## 四、和你要求的对照：已经有的 / 还缺的

| 你的要求 | 参考文件怎么做的 | 我们现在 | 结论 |
|---|---|---|---|
| 边缘线条重构 | 边界=弧/曲线拟合 | `contour.fit_cubic`（只有三次） | **已补圆弧**（见第五节） |

## 五、这一轮已经照参考补上的：圆弧/二次曲线拟合

参考文件的曲线词汇里 A、Q 占一半以上；我们原来只有 L+C。已在 `lumina_vec/layered.py` 加入
`fit_arcs_closed()` 与 `_cubic_to_arc()`：

1. 两条转角之间先试**整段圆弧**（最小二乘圆拟合，偏差 < 0.45 px、弧长 < 330°）；
2. 拟合不上时走原来的 `fit_cubic` 链；
3. 每个三次贝塞尔再试一次"采样点是否落在圆上"，能转成弧就输出 `A`。

480×480 局部实测（同一张图、同一填色层）：

| | 弧 A | 三次 C | 直线 L | 文件 | 段数 |
|---|---|---|---|---|---|
| 关 | 0 | 11,189 | 20,526 | 918 KB | 31,715 |
| **开** | **5,825** | 5,449 | 20,526 | **862 KB** | 31,800 |

弧段占曲线段 **52%**（和参考文件的 30%~55% 同一量级），文件小 6%，渲染肉眼无差别
（`data/struct/cmp-arcs.png`）。圆弧是标准 SVG 命令，Illustrator / Figma / Inkscape / 浏览器都认。

## 六、下一步要抄的三件事（按价值排序）

1. **填色改成"叠放 + 洞"**（参考 deep.svg 有 3.4 万个孔）：形状 = 自己 ∪ 后画区域，
   `fill-rule="evenodd"`。效果是明确的"封闭边界 + 空腔"，而且不需要给面片做 1 px 外扩；
   代价是形状更大、面积重叠，但结构最接近参考。
2. **同色合并成一个 `<style>` 类**：参考里 Illustrator 家族用 `.stN`；我们 16k 个 path 各写一遍
   `fill="#xxxxxx"`，一个色平均出现几十次。做成类能省 10~20% 体积，导入端支持 CSS 就没问题。
3. **渐变换光影**：对面积大、内部有渐变的区域，拟合一个两/三色标 `linearGradient`（方向 + 端点色），
   代替现在"多切几档色带"。这正是 Illustrator 家族显得"有画感"的原因，也正好对应你说的
   "为区域赋予光影/色彩变化"，而且它和"线条层分段上色"是两套互补的机制。

## 七、结论

- 参考图的"高级感"主要来自 **曲线词汇（弧+二次）+ 面片带洞 + 单一色块无重叠**，不是来自颜色数量；
- 我们现在缺的是 **弧/二次拟合**、**叠放成洞**、**渐变光影**、**样式类去重**；
- 弧拟合已经在 `layered` 里默认开启；剩下三项可以按上面的顺序做，彼此不冲突。

## 八、按参考实现的"Lumina 风格"原型（`lumina_vec/regionsvg.py`）

在候选版里新增了 `vectorize_regions()`，结构完全照参考：

```
<g id="fills" fill-rule="evenodd">
  <path class="qq3d-gap-filler" .../>   ← 同色遮缝描边（和参考文件一模一样，导入端会删）
  <path d="..." fill="#rrggbb" fill-rule="evenodd"/>   ← 一条闭合色块（叠放，带空腔）
  ...
</g>
<g id="line-art">…</g>   ← 可选：连续线条层（一条线一个 path）
```

流程：AI 去颗粒 → 均值漂移 → OKLab k-means 量化（`colors` 可调）→ 碎区吸收 →
`contour.region_paths` 叠放描摹（形状 = 自己 ∪ 后画区域，自带空腔）→ **圆弧化**（`arcify`：
把接近圆的三次贝塞尔改写成 `A`）→ 加遮缝描边。

实测（`data/gojo/input.png` 的 480×480 局部）：

| 配置 | path | 弧 A | 三次 C | 文件 | 耗时 |
|---|---|---|---|---|---|
| 128 色，无弧 | 1,728 | 0 | 12,862 | 716 KB | 21 s |
| **128 色，弧** | 1,860 | **10,990** | 2,352 | **650 KB** | 21 s |
| 256 色，无弧 | 1,944 | 0 | 13,572 | 770 KB | 24 s |
| **256 色，弧** | 1,970 | **11,260** | 2,426 | **673 KB** | 26 s |

圆弧占曲线段 **82%**（比参考文件的 30~55% 还高，因为叠放描摹出来的边界更"圆"，拟合更容易成功），
文件小 9~12%。

**当前状态：原型能出图，但还有残余缺陷** —— 面积 <24 px 的小色块被吸收后仍会零星留白点
（2~6 px 的白点，在深色头发里最明显）。原因是叠放描摹只保留"与自身连通"的后画区域，
夹在两个形状之间、又小于 `min_area` 的区域没有下层兜底。**所以还没有接进 UI**；
接进去之前要先修这个（把碎块并入邻居改成"按邻接面积最大者整块替换"，或给整张图加一层底色兜底）。

## 九、接下来的顺序（建议）

1. 修白点：整图加一层"底色兜底"（取量化图的最大面积颜色，铺满画布，最先画），
   这样任何漏掉的区域都不会露白 —— 一行代码，风险最低；
2. 把 `--structure regions` 接进 UI（颜色数用现有的"颜色数"滑杆）；
3. 线条层默认打开，让发丝是一条完整 path；
4. 再考虑同色 `<style>` 类去重（纯体积）。
