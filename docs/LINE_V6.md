# 线条层优化：从"按段拼"到"一条线一个 path"（Lumina-Vec v6）

> 针对的反馈：转换出来的 SVG 里，发丝、描边、轮廓会被切成**一节一节**的小段，
> 只是把这些段画出来时位置对得上，看起来才像连续的线。
> 本文写清楚：这个问题是怎么产生的、改了什么、为什么这么改、改完的效果和代价、以及怎么按画风调参。

---

## 0. 一句话结论

旧版线条层的产物是"**每条线切成 N 段 × 每段一个 `<path>`**"（段间是垂直直切口、线宽和颜色各段各算）。
新版（v6）把它改成"**一条线 = 一个 `<path>`**"：左右两条边各是一条连续曲线链，只在真转角处断开，
末端圆头、自由端收尖，线宽和颜色按整条线统一；交叉处剩下的碎片再用"能否被一条贝塞尔拟合"接回整条。

实测四张图：path 数 **−20% ~ −44%**，path 中位长度 **+38% ~ +90%**，10 px 以下碎片 **−63% ~ −78%**，
对模型线稿的覆盖率 **+8 ~ +12 个百分点**，线条层耗时 **−20%** 左右，整图颜色数 **−31% ~ −36%**。

## 1. 背景：旧版为什么是碎的

### 1.1 旧版的数据结构

```
线稿模型 M / A
   └─ P = max(M/0.6, A/0.5)                    线概率图
        └─ 骨架化 → 交叉点拆成"分枝" → 交叉处按方向把分枝配对成"笔画(chain)"
             └─ adaptive_pieces(): 每条笔画再按"误差 / 转角"切成若干段
                  └─ lens_paths(): 每段输出一个 <path>
                       每条边一条三次贝塞尔，段两端用 L 命令直切
```

关键点：**"段"不是实现细节，它直接出现在输出文件里**。一条 2000 px 的发丝，骨架可能会被切成
4~10 段，于是 SVG 里就有 4~10 个 `<path>`，每个都有自己的闭合轮廓。

### 1.2 "看起来完整"是怎么来的

每段是一个"双贝塞尔透镜"：左边界一条三次贝塞尔、右边界一条、两端用直线封口。相邻两段的封口边
垂直于线、彼此重合，所以渲染出来接缝几乎看不见；但：

- **结构上**是 N 个独立形状，不是一条线；
- **线宽**每段单独测量、单独高斯平滑，段边界上宽度会跳一下（`smooth_px=3` 在段内平滑，段端被截断）；
- **颜色**每段单独取（该段中心线较暗一半像素的均值），同一条发丝可能出现 2~4 种颜色；
- 下游（Lumina-Layers 多色分层、切片、编辑）会把这些段当成 N 个独立区域。

### 1.3 三个具体断点

| 断点 | 位置 | 现象 |
|---|---|---|
| A. 段级输出 | `lens_paths` | 一条线本来就输出多个 path，这是"碎"的根因 |
| B. 交叉处配对失效 | `strokes2.build_strokes`：`join_cos=-0.7` | 骨架在交叉点会拐弯，端点方向配不上，线在交叉处断成两段 |
| C. 粗块判据用模型宽度 | `strokes2.blob_mask` | 模型画线本来就比实际粗 2~3 倍，`distanceTransform(P>0.5) > 2.5` 会把整条发丝判成"填充块"，一半发丝从线条层消失 |

## 2. 怎么量化"碎"

靠"看起来"判断不了，所以做了两套可复现的测量（脚本都在 `D:\DSH-DATA\20261113-2130-lumina-vec\scripts`）：

### 2.1 线条层指标（任意图都能跑）

`bench_style.py` 只跑线条层（模型输出已冻结成 `M.npy/A.npy`，不重复占用 GPU），输出：

| 指标 | 含义 | 期望方向 |
|---|---|---|
| `n_paths` | `<path>` 个数 | ↓ |
| `stroke_len` 分位数 | 把轮廓周长/2 当作笔画长度 | ↑（越长说明越连贯） |
| `short_paths.lt10` | 低于 10 px 的碎片数 | ↓ |
| `n_ink_components` | 画出来以后连通块数量 | ↓（线连成整体） |
| `recall_vs_model` | 画出的墨与模型线稿的重合度 | ↑（有没有漏线） |
| `n_colors` | 用到的颜色数 | ↓（一条线一种颜色） |

> 细节：项目自带的 `svgraster.path_polys` 每条三次贝塞尔只展 10 个点，量 2000 px 的长线会严重切角，
> 所以改用 `dshbench.py` 的 1 px 精度展平再栅格化。这一点也是我最初被误导的原因（见 6.3）。

### 2.2 合成发丝图（有 ground truth）

`make_hair_synth.py` 生成一张 1500×1100 的图：48 条**已知中心线**的发丝（宽 1.0~2.2 px，带交叉、
带"淡出的中段"）、3 条粗轮廓，同时导出 `hair_synth.json`（每条发丝的参数点）。
`bench_strands.py` 沿着已知中心线采样，记录每一点被哪个 `<path>` 覆盖，于是能直接回答
"一条发丝被几个 path 拼出来的"。

## 3. 优化思路

### 3.1 总原则：让**数据**连续，而不是让渲染看起来连续

只要一条线在文件里是多个形状，接缝、宽度台阶、颜色碎片就会一路传到下游。所以优化目标定为：
**一条线在 SVG 里必须是一个 `<path>`**，其余所有改动都为这条服务。

### 3.2 为什么不用 `<path d="..." stroke="#000" stroke-width="2"/>`

看起来最省事的做法是把中心线直接输出成描边（stroke）。否掉的原因：

- 这条流水线的线**宽度沿长度变化**（发丝起笔粗、收笔细，轮廓有粗细变化），
  `stroke-width` 是常量，做不出变宽；
- 下游 Lumina-Layers 和切片软件按**填充区域**处理，描边要额外做"轮廓化"，等于把工作推到下游；
- 打印模式要求每条线有确定的最小线宽，填充形状才好控制。

结论：仍然用"闭合填充轮廓"，但**整条线只用一个轮廓**。

### 3.3 一条线的轮廓怎么闭合成一个 path

一条有宽的线，几何上是"中心线 ± 半宽"的两条偏移曲线加两个端帽。做法：

```
d = M 左边界起点
    C ...(左边界按曲线链走完，只在真转角处断)
    C ...(末端：非自由端画半圆帽；自由端宽度收到 0，自然收成尖)
    C ...(右边界反向走回起点)
    C ...(起始端同理)
    Z
```

要点：

- 左、右边界各自用 `contour.fit_cubic`（Schneider 算法）拟合：它在误差最大处切分，
  切分点两侧用**同一个弦切方向**重建，所以链内是 C1 连续的——不会出现"折角"；
- 只在中心线**真转角**（`_turn_corners`，>40°）处断链：那里断开在视觉上是正确的拐角，不是接缝；
- 自由端把宽度收到 0（`width_profile` 的 taper），两条边界在端点重合，闭合时不需要端帽；
- 非自由端（交叉处/粗块边缘）画半圆帽（两段三次贝塞尔，k=0.5523），比旧的垂直直切口更自然。

### 3.4 为什么整条线一次测宽

旧版：每段单独 `_width_at` + `gaussian_filter1d(w, 3)`，段两端被截断 → 段边界出现宽度台阶。
新版 `width_profile()`：在**整条**中心线上测宽、整条一次平滑，再在自由端做收尖：

```
w = min(模型宽, 原图墨宽)           # 原图墨宽优先，防止模型把线画粗
w = gaussian(w, 3)                 # 沿整条线
w *= clip(0.92 * s / taper, 0, 1)  # 端部收尖（s = 距端点的弧长）
```

### 3.5 合并判据：为什么用"单贝塞尔能否拟合"而不是"端点方向"

交叉处骨架会拐弯，端点方向（`_out_dir`，取 5~6 px 的差分）噪声很大，旧的 `cos < -0.7` 判据经常
把同一条线判成"不连续"。新判据 `_join_fit()`：

1. 把两段拼起来，用**一条**三次贝塞尔最小二乘拟合（重新参数化 3 轮）；
2. 误差上限按长度缩放：`clip(0.025·L, 1.0, 3.0)` px；
3. 拟合不上时允许拆成**两条**（S 形发丝），但更多条就拒绝——那通常意味着这里是交叉、不是延续；
4. 接缝两侧各 25 px 范围内必须有墨（`P` 均值 > 0.15），避免"跨过空白去接另一根线"。

一次实测：`bridge_strokes` 后的 509 段 → `merge_strokes` 后 406 段（旧版这一步在 v5 里几乎不生效）。

> 试过但放弃：用"合并后曲线与高斯平滑版的偏差 > 1.25 px 判为折角"来判接缝。阈值对曲线本身太敏感，
> 几乎拒绝所有合并（509 段仍是 509 段）。

### 3.6 淡线：滞回（hysteresis）而不是降阈值

线稿模型在淡线（浅灰轮廓、发丝尾端）上的输出常常掉到 0.3~0.5，旧的硬阈值 0.5 就在那里切断。
直接把阈值降到 0.3 会到处冒出散碎线。采用滞回：

```
强线 = P > 0.50
弱线 = 0.30 < P ≤ 0.50，且所在连通块碰到强线（膨胀 1 px 邻接）
弱线被采纳时抬到 0.62 → 进入后续骨架/描边
```

实测（覆盖率 / 背景里多出来的墨）：

| 图 | 关 | weak=0.30（默认） | weak=0.22 |
|---|---|---|---|
| 雷电 | 0.846 / 1.13% | **0.862 / 1.58%** | 0.867 / 1.88% |
| 海边 | 0.845 / 0.79% | **0.857 / 1.37%** | 0.861 / 1.65% |

代价是背景里多 0.4~0.8% 的墨（多数是模型漏掉的真实淡线，也有少量伪线），默认取 0.30。

### 3.7 粗块：按**原图墨色宽度**判，不按模型宽度

`blob_mask` 决定"这是填充块（睫毛根、眼线）还是笔画"。旧版用模型掩码的宽度：

```
core = distanceTransform(P > 0.5) > wide_px/2      # ← 用的是模型掩码
```

线稿模型画线天生比实际粗 2~3 倍，于是整条普通发丝都满足"宽度 > 5 px"，被判成粗块：
结果这条发丝只有一部分以笔画输出（其余部分被当成"填充块"），线条层里就出现"半条发丝"。
新版改成按原图墨色：

```
core = distanceTransform(ink > 0.35) > wide_px/2   # ink = ink_field(原图) 覆盖度
blob = dilate(core) & (P > 0.5)
```

对照实验（同一套 v6 笔画代码，只换这一处）：

| 图 | 模型宽度判据（旧） | 原图墨宽判据（新） |
|---|---|---|
| 雷电 | 1011 path / 覆盖 0.825 | **812 path / 0.862** |
| 海边 | 806 path / 覆盖 0.840 | **627 path / 0.857** |
| 合成发丝 | 686 path / 覆盖 0.881 | 751 path / 0.893 |

真实插画上 path 更少、覆盖更高；合成图上 path 略多（因为不再被当成块），覆盖仍更高。

### 3.8 其他小改动

- 丢掉落长度 < 2 px 的残渣（旧版会在发丝旁边留下细碎短条，被算进碎片）；
- `_join_fit` 之前先做 `bridge_strokes`（端点 14 px 内、外向方向不成锐角、长桥上要有淡线），
  两遍合并负责不同的断点：交叉点用拟合判据，真正的空隙用几何桥接；
- 所有新逻辑只在**显示模式**的 `line_style=lens` 生效；打印模式仍走 v3/contour（最小线宽优先）。

## 4. 实现（代码地图）

`lumina_vec/draw.py` 新增（旧 `lens_layer` 改名 `lens_layer_legacy` 完整保留）：

| 函数 | 职责 |
|---|---|
| `line_strokes(P, cov, wmin, spacing)` | 整条线：`build_strokes` → `bridge_strokes` → `merge_strokes` → 丢残渣 → 测宽。返回 `[{pts, w, free}]` |
| `stroke_outline_d(pts, w, free, tol, corner_deg)` | 一条线的闭合 `d`：左边界链 + 端帽 + 右边界链 + 闭合 |
| `_edge_chain(edge, cuts, tol)` | 把一条边界按"转角切分"的区间分别用 `fit_cubic` 拟合成曲线链 |
| `_half_circle(c, u, v, r)` | 非自由端的半圆端帽（两段三次贝塞尔） |
| `width_profile(pts, P, cov, ...)` | 整条线测宽 + 平滑 + 端部收尖 |
| `bridge_strokes(items, P, spacing, ...)` | 端点几何桥接（空隙补线） |
| `merge_strokes(items, P, gap_max, cos_max, ...)` | 按拟合判据合并（交叉处修复） |
| `_join_fit(pi, pj, P, ...)` | 两段能否是一条线：单贝塞尔（S 形允许两条）+ 接缝有墨 |
| `hysteresis(P, strong, weak, boost)` | 淡线滞回 |
| `stroke_paths(items, rgb, wmin, tol)` | 每条线一个 `<path>`、一个颜色 |
| `lens_layer(geo, M, A, debug, hyst_weak, tol)` | 对外入口：概率图 → 粗块/圆点 → 笔画 → SVG 路径 |

关键伪代码（`stroke_outline_d`）：

```python
tang = 单位切向; nrm = 法向; half = w/2
Lf = pts + nrm*half;  Rt = pts - nrm*half
cuts = [0] + 真转角处 + [n-1]
d = "M Lf[0]"
for 每个 cuts 区间:                      # 左边界正向
    d += C(用 fit_cubic 拟合 Lf[a:b] 的曲线链)
if 非自由端: d += C(半圆端帽)
for 每个区间（反向）:                     # 右边界反向
    d += C(用 fit_cubic 拟合 Rt[b:a] 的曲线链)
if 非自由端: d += C(起点半圆端帽)
d += "Z"
```

`lumina_vec/strokes2.py`：`blob_mask` 的宽度判据改成原图墨色（见 3.7），其余未动。

`lumina_vec/pipeline.py` / `webui.py`：`--line-style` 增加 `lens5`（旧实现），默认 `lens` 走 v6。

## 6. 怎么按画风调参（实战手册）

| 想要 | 改哪里 | 说明 |
|---|---|---|
| 线更连贯（交叉处也接上） | `merge_strokes(cos_max=-0.5 → -0.2)` | 放宽"两段方向不能成锐角"的限制；配 `_join_fit` 的拟合判据，误合并有限 |
| 线更干净（少画伪线） | `lens_layer(hyst_weak=0.30 → 0.0)` | 关掉淡线滞回，覆盖率降 1~2 个点，背景墨少 0.4~0.8% |
| 更多淡线 | `hyst_weak=0.30 → 0.22` | 覆盖率 +0.5 个点，伪线也更多 |
| 文件更小 | `stroke_outline_d(tol=0.45 → 0.9)` | 曲线段更少，肉眼几乎无差别 |
| 发丝更细/更粗 | `width_profile(wmin=0.8)` | 最小线宽；打印模式另有 `line_min` 逻辑 |
| 睫毛根别变成糊块 | `blob_mask(wide_px=5.0 → 6.0)` | 阈值越高，越少区域被当成填充块 |
| 想看调试数字 | `lens_layer(geo, M, A, debug=True)` | 额外返回 `n_strokes / median_width_px / cubics` |

## 7. 已知限制（如实说明）

1. **密集交叉区仍可能分成 2~4 段**。两段是"同一条线的延续"还是"另一根发丝"，在交叉点上几何信息不足；
   现在用"单贝塞尔拟合 + 接缝有墨"来合，能合掉大部分，但不是全部。
2. **合成发丝图的"段数"指标没有明显下降**（`nbig_mean` 4.28 → 4.88，`distinct_mean` 10.4 → 16.4）。
   原因是那张图极密（48 条 × 10 多次交叉），沿中心线采样时每经过一个交叉点就会被"另一条线的 path"
   覆盖一小段，指标本身在数交叉，而不是在数碎片；同时模型在那张图上的输出特别粗，
   新旧粗块判据都在反复切它。**真实插画上的四项指标（5.1/5.2）才是有效证据**。
3. **模型漏检的淡线救不回来**（P < 0.3），例如浅蓝线画在浅蓝头发上。
4. 大图（工作尺寸 > 2.5k）没有实测；`eye_boxes`（眼睛专用通道）没有单独回归。
5. 打印模式（`--print-mm`）不经过这条路径，结果不变。

## 9. 附录：指标定义

| 名称 | 定义 |
|---|---|
| path 中位长度 | 把 `<path>` 展平（1 px 精度）后取轮廓周长的一半，作为该笔画长度；对所有 path 取中位数 |
| 10 px 以下碎片 | 上述长度 < 10 px 的 path 数（多数是残渣、点、碎片） |
| 连通块 | 把所有 path 栅格化后 8 邻域连通分量数；线越连成整体，这个数越小 |
| 覆盖率 recall | 栅格化结果与模型线稿 `P>0.5` 的交集 / 模型线稿面积 |
| extra | 栅格化结果落在模型线稿之外的比例（相对背景面积），用来衡量"多画了多少" |
| `nbig_mean` | 每条 ground-truth 发丝被多少个"覆盖它 ≥5% 采样点"的 path 覆盖（平均） |
